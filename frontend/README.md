# Relationer — конструктор родства

Локальное SPA на Vue 3, TypeScript, Vite и Vue Flow. День 8.1: построение графа с упрощёнными действиями и мобильными нижними панелями; запросы поиска не отправляются.

## Запуск

Нужны Node.js >= 22.12 (версия в `.nvmrc`: 22.22.0), npm и JDK 21.

```sh
cd frontend
# Если используется nvm:
nvm install
nvm use
npm ci
npm run dev
```

Vite выведет локальный адрес. `npm run preview` запускает собранный `dist/`.

Если появляется ошибка `os__default.availableParallelism is not a function`, проверьте `node -v`: терминал или IDE использует старый Node.js. Для подготовленного локального Node.js 22.22.0 из каталога `frontend`:

```sh
export PATH="$PWD/.cache/node/bin:$PATH"
node -v # v22.22.0
npm run dev
```

Команда `export` действует для текущего терминала. В IDE выберите Node interpreter `frontend/.cache/node/bin/node` либо установленный через nvm Node.js 22.

## Проверки

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
```

Браузерные тесты запускают отдельный Vite dev server на порту 4173 и используют установленный Google Chrome. Режим разработки позволяет проверять фактический вычисленный SearchRequest через инструменты Vue без добавления тестовых методов в приложение. Production build проверяется отдельно. Альтернатива: `npx playwright install chromium`, затем `PLAYWRIGHT_CHANNEL=chromium npm run test:e2e`.

Снимки интерфейса находятся в `artifacts/`: `editor-desktop.png`, `editor-common-parent.png`, `editor-mobile-320.png`, `editor-mobile-375.png`, `editor-mobile-390.png`, `editor-mobile-768.png`. Браузерные тесты создают их заново.

Мобильные сценарии используют touch-эмуляцию Chromium: нажатия на карточки, общий родитель, нижние панели, отсутствие скролла страницы, сворачивание панели, fitView, перетаскивание, перемещение холста и pinch zoom. Цепочка через супруга, духовные связи, разные типы между одной парой и правильный SearchRequest также проверяются в браузере.

## Состояние

`EditorState.graph` содержит `persons`, `relations`, `personA`, `personB`. Люди и типы связей используют сгенерированные DTO. Связь редактора расширена внутренним ID для выбора и удаления.

`EditorState.positions` хранит только координаты по ID человека. Vue Flow получает вычисляемые проекции nodes/edges; перемещение узла записывается обратно в positions. Размеры отображаемых карточек остаются внутренним состоянием Vue Flow.

ID A и B фиксированы (`person-a`, `person-b`) и сохраняются при переименовании и сбросе. Дополнительные ID создаёт `crypto.randomUUID()`.

`toSearchRequest()` возвращает сгенерированный `SearchRequest`, исключая координаты и внутренние ID связей. Возвращённые массивы и записи не разделяют изменяемые объекты с редактором.

## Действия

- Выбрать человека на холсте или через кнопки A/B.
- Для выбранного человека доступны три действия: «Добавить родственника», «Связать с существующим», «Переименовать».
- Переименование открывается отдельно; сохранить имя можно кнопкой или Enter.
- Добавить одного из семи видов родственников.
- Соединить существующих людей: выбрать человека и его роль относительно выбранного. Предварительный просмотр показывает фактическое направление связи.
- В меню «Ещё» доступны связи и удаление. Можно также выбрать линию на холсте и открыть её вторичное меню.
- Удалить дополнительного человека с его связями; A и B защищены.
- Перемещать карточки, масштабировать и перемещать холст.
- Показать весь граф кнопкой fitView.
- Сбросить граф через меню «⋯» в панели холста. Потеря нескольких связей требует подтверждения.

На ширинах до 768px холст занимает свободную высоту экрана, действия выбранного человека находятся в компактной нижней панели. Её можно свернуть, чтобы увеличить холст. Добавление, связь, переименование и подтверждение открываются как нижние модальные панели с собственным скроллом. Холст принимает touch-жесты; панели сохраняют обычную прокрутку. Все действия доступны нажатием, без hover.

Связи хранят направление «родитель → ребёнок», «крёстный → крестник», «приёмный родитель → приёмный ребёнок». Брак симметричен. Одинаковые связи запрещены; разные типы между одной парой допускаются.

## Родители и семейные связи

Каждый узел представляет отдельного человека. Для общего родителя используйте «Добавить родственника» → «Родителя», затем свяжите его с существующим ребёнком. Второго родителя и брак добавляйте явно при необходимости; условных родительских групп нет.

В панели действий доступна компактная раскрывающаяся подсказка «Как добавить родителей» с пояснениями: `<BB>` — кровное родство через общего родителя; `<BMB>` — путь через брак родителей, который может обозначать свойство между детьми разных супругов. Подробности — в [документации семейных связей](../docs/family-groups.md).

## API-first

Единственный контракт — `../backend/openapi.yaml`. `npm run api:generate` запускает официальный OpenAPI Generator JAR **7.17.0**, генератор `typescript-fetch`. JAR загружается из Maven Central в `.cache/`, его SHA-256 проверяется при запуске. Версия совпадает с backend.

Генерация автоматически выполняется перед dev, typecheck, тестами и build. Сгенерированные файлы нельзя редактировать. При первом запуске нужен доступ к Maven Central; после загрузки JAR генерация работает локально.

## Ограничения

Черновик живёт в памяти вкладки и теряется при обновлении. Автоматической раскладки сложных деревьев, undo/redo, хранения, расчёта родства, запросов к backend и результатов поиска пока нет. Операции редактора проверяют ссылки и дубликаты, но не интерпретируют канонические правила и не проверяют достоверность родословной.
