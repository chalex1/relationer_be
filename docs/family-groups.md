# Родители и семейные связи в конструкторе

Каждый узел Relationer представляет отдельного человека. Семья задаётся обычными персонами и явными связями: `BIOLOGICAL` — родитель → ребёнок, `MARRIAGE` — брак. Отдельного типа узла «Родители», условной группы и преобразования группы в техническую персону нет.

## Сколько родителей добавлять

В конструкторе доступна раскрывающаяся подсказка «Как добавить родителей»:

> Если для определения родства достаточно одного общего родителя, добавьте только его. Для подробного семейного дерева можно добавить обоих родителей, браки и детей от разных союзов.

Для одного общего родителя:

1. Выберите A, затем «Добавить родственника» → «Родителя».
2. При необходимости переименуйте добавленного человека.
3. Для него выберите «Связать с существующим», укажите B в роли «Ребёнок».

Получатся три человека и две связи `BIOLOGICAL`. Второй родитель и брак автоматически не создаются.

Для двух общих родителей повторите эти действия от A, создав второго отдельного человека и связав его с B. Брак добавляется отдельно: выберите одного родителя, затем «Связать с существующим» и второго в роли «Супруг / супруга».

Детей от разных союзов добавляйте к соответствующим людям. Брак сам по себе не создаёт общих детей или связей с детьми супруга.

## Коды родства

- `<BB>` — кровное родство через общего родителя: `A → общий родитель → B`.
- `<BMB>` — путь через брак родителей, который может обозначать свойство между детьми разных супругов: `A → родитель A → супруг родителя A → B`.

Эти коды не взаимозаменяемы. Два общих родителя дают отдельные кровные пути через каждого из них. Конструктор сохраняет введённых людей и связи, не вычисляет коды и не заменяет один путь другим. Семантика поиска и фильтрация избыточных обходов описаны в [модели родства](architecture/kinship-model.md).

## Редактирование и запрос

Для любого человека доступны все семь действий: добавить родителя, ребёнка, супруга, крёстного, крестника, приёмного родителя или приёмного ребёнка. Можно соединять существующих людей, переименовывать и перемещать их, удалять связи и дополнительных людей. Участники A и B защищены от удаления. Одинаковые связи запрещены; разные типы связей между одной парой допускаются.

В `SearchRequest` каждый человек передаётся как одна обычная персона с `id` и `name`, а связи — с `type`, `from`, `to`. Координаты и внутренние ID связей не передаются. Кнопка «Найти совпадения» отправляет запрос через сгенерированный клиент на backend. В панели «Участники и результаты» можно выбрать любых двух разных людей графа для A/B; результаты очищаются после изменения графа или пары. [Подключение и реальные примеры](day9-integration.md).

Каталог `/references` показывает те же виды связей через общий компонент графа,
но не редактирует людей и не загружает эталон в конструктор. [Текущее устройство](architecture/overview.md).
