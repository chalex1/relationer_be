# Спецификация поиска справочных деревьев

## 1. Назначение и область поиска

Документ описывает сопоставление справочных структур из базы случаев с графом, построенным пользователем. Термины и типы связей согласованы с `docs/kinship-rules.md` и правилами R01–R13.

Пусть `P` — `ReferencePattern` (справочный шаблон), а `G` — `UserGraph` (пользовательский граф). Совпадение существует, если существует инъективное отображение `f: V(P) → V(G)`, при котором для каждого обязательного направленного ребра шаблона `u → v` типа `t` в `G` присутствует ребро `f(u) → f(v)` того же предметного типа и роли. Направление сохраняется; порядок расположения на экране, имена и идентификаторы людей не участвуют в определении совпадения.

Это поиск неизоморфного в общем случае, неиндуцированного подграфа: в `G` разрешены дополнительные узлы и дополнительные рёбра, в том числе между уже сопоставленными узлами (M01). Все обязательные узлы и рёбра шаблона должны быть явно представлены. Неизвестное ребро не считается совпавшим, а транзитивные связи автоматически не добавляются. Брак (`MARRIAGE`) не заменяет кровную (`BLOOD`) или духовную (`SPIRITUAL`) связь. Пол участника игнорируется только для роли крестного родителя (M02).

Один и тот же шаблон может иметь несколько отображений. Каждое различное множество пар `patternNodeId → userNodeId` считается отдельным уникальным вхождением (M03). Поиск выполняется по всему `G`; выбранная пользователем пара не ограничивает множество отображений (M04).

**M05. Минимально достаточная структура родства.** Если шаблон содержит двух братьев, связанных через одного общего родителя, наличие этого общего родителя в `G` достаточно для совпадения. Дополнительные родительские связи не препятствуют совпадению. Второй общий родитель не требуется, если он не указан обязательным ребром шаблона; если шаблон явно требует двух общих родителей, должны совпасть оба обязательных ребра.

### 1.1. Концептуальные структуры

`ReferencePattern` содержит идентификатор шаблона, узлы с ролями и обязательные направленные рёбра. Ребро имеет предметный тип (`BLOOD`, `MARRIAGE`, `AFFINITY`, `SPIRITUAL`) и, если применимо, роль (например, `parent`, `godparent → godchild`).

`UserGraph` содержит условные идентификаторы участников и явно заданные направленные или ненаправленные связи с теми же типами и ролями. Идентификаторы используются только для хранения результата, а не для проверки семантического равенства.

### 1.2. Результат

Для каждого найденного вхождения доступны:

- `referenceCaseId` — идентификатор справочного случая;
- `occurrenceId` — идентификатор конкретного вхождения;
- `patternNodeId → userNodeId` — полное инъективное отображение узлов;
- идентификаторы сопоставленных участников;
- `referenceCaseData`, включая явно заданные в справочнике разрешение или запрет, если они есть;
- основание совпадения: идентификатор и описание найденного `ReferencePattern`.

Статус поиска (`MATCH` или `NO_MATCH`) отделён от канонического вывода справочного случая. Система не вычисляет разрешения или запреты самостоятельно и не выводит их из отсутствия совпадения.

## 2. Тестовые сценарии

Во всех примерах стрелка означает направление роли; идентификаторы условны.

### T01 — Точное совпадение

- **ReferencePattern:** узлы `p1`, `p2`; ребро `p1 → p2: BLOOD/parent`.
- **UserGraph:** узлы `u1`, `u2`; ребро `u1 → u2: BLOOD/parent`.
- **Ожидание:** `MATCH`, 1 вхождение.
- **Объяснение:** отображение `p1→u1`, `p2→u2` сохраняет обязательный тип и направление; лишних вариантов нет.
- **Правила:** R01, R13; M01, M03.

### T02 — Дополнительный участник

- **ReferencePattern:** узлы `p0`, `p1`, `p2`; рёбра `p0 → p1: BLOOD/parent`, `p0 → p2: BLOOD/parent` (один общий родитель двух братьев; второй общий родитель не обязателен).
- **UserGraph:** узлы `u0`, `u1`, `u2`, `u3`; рёбра `u0 → u1: BLOOD/parent`, `u0 → u2: BLOOD/parent`, `u3 → u1: BLOOD/parent`.
- **Ожидание:** `MATCH`, 2 вхождения.
- **Объяснение:** `u3` — дополнительный участник и дополнительный родитель `u1`. Второй общий родитель отсутствует, но не требуется шаблоном. Два уникальных отображения возникают из-за симметрии братьев: `p0→u0, p1→u1, p2→u2` и `p0→u0, p1→u2, p2→u1`.
- **Правила:** R01, R02, R13; M01, M03, M05.

### T03 — Дополнительная связь

- **ReferencePattern:** узлы `p1`, `p2`; ребро `p1 → p2: BLOOD/parent`.
- **UserGraph:** узлы `u1`, `u2`, `u3`; рёбра `u1 → u2: BLOOD/parent` и `u1 — u3: MARRIAGE/spouse`.
- **Ожидание:** `MATCH`, 1 вхождение.
- **Объяснение:** обязательная кровная связь присутствует; дополнительный брак не препятствует совпадению и не подменяет тип связи.
- **Правила:** R01, R05, R10; M01.

### T04 — Не хватает обязательной связи

- **ReferencePattern:** узлы `p1`, `p2`, `p3`; рёбра `p1 → p2: BLOOD/parent`, `p1 → p3: BLOOD/parent`.
- **UserGraph:** узлы `u1`, `u2`, `u3`; присутствует только `u1 → u2: BLOOD/parent`.
- **Ожидание:** `NO_MATCH`, 0 вхождений.
- **Объяснение:** участники есть, но второе обязательное ребро отсутствует; неизвестность не считается совпадением.
- **Правила:** R01, R11; M01.

### T05 — Различается тип связи

- **ReferencePattern:** `p1 → p2: SPIRITUAL/godparent → godchild`.
- **UserGraph:** `u1 → u2: BLOOD/parent`.
- **Ожидание:** `NO_MATCH`, 0 вхождений.
- **Объяснение:** направление одинаково, но духовная роль и тип не совпадают с биологическим родительством; кровная связь не считается духовной.
- **Правила:** R01, R07, R13; M02.

### T06 — Пол крестного различается

- **ReferencePattern:** `p1 → p2: SPIRITUAL/godfather → godchild`.
- **UserGraph:** `u1 → u2: SPIRITUAL/godmother → godchild`.
- **Ожидание:** `MATCH`, 1 вхождение.
- **Объяснение:** тип `SPIRITUAL`, роль крестный → крестник и направление сохранены. Пол крестного игнорируется специально для этой роли.
- **Правила:** R07, R13; M02, M03.

### T07 — Два независимых вхождения

- **ReferencePattern:** `p1 → p2: SPIRITUAL/godparent → godchild`.
- **UserGraph:** рёбра `a1 → a2: SPIRITUAL/godparent → godchild` и `b1 → b2: SPIRITUAL/godparent → godchild`; фрагменты не связаны между собой.
- **Ожидание:** `MATCH`, 2 вхождения.
- **Объяснение:** существуют два разных отображения: `{p1→a1,p2→a2}` и `{p1→b1,p2→b2}`. Они возвращаются отдельно, хотя ссылаются на один справочный случай.
- **Правила:** R07; M03.

### T08 — Совпадение вне выбранной пары

- **Выбранная пара пользователя:** `A`, `B`.
- **ReferencePattern:** `p1 → p2: BLOOD/parent`.
- **UserGraph:** узлы `A`, `B`, `C`, `D`; ребро `C → D: BLOOD/parent`; между `A` и `B` нет структуры шаблона.
- **Ожидание:** `MATCH`, 1 вхождение.
- **Объяснение:** шаблон найден в части графа `C,D`, независимо от выбранной пары `A,B`; результат сохраняет отображение `p1→C`, `p2→D`.
- **Правила:** R01, R13; M04.

## 3. Open Questions

В `docs/kinship-rules.md` вопрос 10 оставляет открытым сам критерий совпадения. Настоящий документ фиксирует согласованное для этой задачи решение: направленное инъективное сопоставление обязательных рёбер как неизоморфный неиндуцированный подграф, с допуском дополнительных узлов и рёбер. Остальные открытые вопросы исходного документа (в частности о неполных данных, вариантах традиций и содержимом справочного разрешения/запрета) не изменяются и требуют отдельного решения; этот документ их не расширяет.
