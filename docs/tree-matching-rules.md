# Спецификация текущего поиска

Действующий поиск сопоставляет коды простых путей **между выбранными A/B**.
Это не поиск произвольного изоморфного подграфа и не поиск вне выбранной пары.
Раннее предложение с отображениями узлов сохранено [в архиве](archive/subgraph-matching-proposal.md).

## Вход и последовательность

`POST /api/v1/references/search` принимает `SearchRequest`: persons, relations,
personA, personB. Люди имеют уникальные непустые ID; ссылки должны существовать,
A и B различны. Типы связей: BIOLOGICAL, MARRIAGE, SPIRITUAL, ADOPTION.
Координаты, имена людей, категории, теги и внешний вид графа не определяют совпадение.

1. `SearchApiMapper` восстанавливает `PersonGraph` и проверяет структуру.
2. `ReferenceSearch` вызывает `PathExtractor.extractForSearch` для графа
   пользователя и каждого эталона общего каталога.
3. Извлекаются простые пути без повторного посещения человека. Связи читаются
   в обоих направлениях; биологическая/духовная/приёмная сохраняют направление роли.
4. Фильтруется конкретный избыточный обход через брак двух общих биологических
   родителей. Исходный граф не меняется; подробности в [модели родства](architecture/kinship-model.md).
5. `PathEncoder` кодирует переходы, `PathMatcher` сравнивает коды.
6. Подходящие пары путей возвращаются как отдельные `ReferenceMatch`.

## Коды и правило сравнения

| Переход | Прямой токен | Обратный токен |
| --- | --- | --- |
| BIOLOGICAL родитель → ребёнок | `B>` | `<B` |
| SPIRITUAL крёстный → крестник | `G>` | `<G` |
| ADOPTION усыновитель → ребёнок | `U>` | `<U` |
| MARRIAGE | `M` | `M` |

`reversePath` разворачивает строку и меняет `<` на `>` и обратно.
`contains` — строковое включение, с проверкой также обратного фрагмента:

- Для FORBIDDEN/UNDETERMINED код эталона содержит пользовательский код
  либо его обратную запись.
- Для ALLOWED пользовательский код содержит код эталона либо его обратную запись.

Это действующая асимметрия, а не проверка полного равенства. Например, `<BB>`
совпадает с более длинными кровными эталонами FORBIDDEN, содержащими этот фрагмент.
Порядок JSON-людей и их положение на экране не участвуют в кодах.

## Результат и ограничения

Ответ `{matches: [...]}` содержит referenceId, verdict, description,
userPathCode, referencePathCode и source. Общий вердикт не вычисляется;
противоречащие случаи сохраняются. Отсутствие совпадений — `matches: []`,
не разрешение брака и не доказательство отсутствия родства.

Разные конкретные пути могут давать одинаковые коды и внешне одинаковые DTO:
API не возвращает последовательности ID людей, occurrenceId или отображения
эталонных узлов в пользовательские. Поиск вне выбранной пары, канонический
расчёт степеней и отдельный ответ «недостаточно данных» не реализованы.
Некорректная структура запроса даёт HTTP 400 `{message}`, а не новый вердикт.
